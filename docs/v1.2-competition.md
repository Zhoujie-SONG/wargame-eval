# V1.2 批量参赛测评与导出

本次实现全部 P0；P1 只实现 **竞赛综合 HTML 报告** 与 **图表导出**。保留 V1.1 模型、Prompt、单任务、评分、加密、SSRF、防超预算和故障重跑逻辑。管理界面仍仅供主办方使用。

## 启动与升级

```powershell
python -m pip install -r requirements.txt
python start.py
```

打开 <http://127.0.0.1:8000>。升级前请停止正在执行的任务并备份 `data/` 与 `config/`。新表通过 `CREATE TABLE IF NOT EXISTS` 增量建立，不删除旧数据库、题库、图片、模型、Prompt 或运行结果。已有模型、Prompt 和单次任务可继续使用。

继续只使用一个服务进程、一个 worker。所有队伍复用原 Runner 顺序执行，不包含并发和速率限制优化。浏览器刷新不影响后台执行；进程重启后已排队/运行的任务标为中断，绝不自动重复发送可能收费的请求。尚未启动的草稿批次保留。

## 正式比赛 02 批量参赛管理

左侧导航按用途分组，各组从 01 独立编号，原有 `data-tab` 和 URL/hash 不变：

- **正式比赛**：01 数据集管理 → 02 批量参赛管理 → 03 批量测评与监控 → 04 竞赛分析与导出 → 05 报告与排行榜（历史结果入口）。
- **开发者选项**：01 模型配置 → 02 Prompt 与推理 → 03 创建测评任务 → 04 任务监控，用于单模型手动调试。

1. 下载 Excel 或 CSV 模板，每行填写一队的一份方案。
2. 上传文件，查看行号、可导入、重复、错误、三段 Prompt 完整性及凭据状态。
3. 有任何错误时整个预览不能确认导入。修正后重新上传。
4. 点击“确认整批导入”，自动创建队伍、方案、模型和 Prompt 关联。此步骤不调用模型、不测试连通性。

字段包括 `team_id`、`team_name`、`submission_version`、`api_base_url`、`api_key`、`api_key_env`、`model_id`、`is_aggregator`、`prompt_system`、`prompt_initial`、`prompt_review`、`temperature`、`max_tokens`，另支持可选 `provider`（默认 `openai`，Mock 使用 `mock`）。三段 Prompt 必须非空，各段最多 20000 字符；仅做字段和格式检查，不审核原始 QA 内容。

CSV 须为 UTF-8（支持 BOM），使用标准引号规则，**包含换行、逗号或引号的单元格须正常引用**；建议使用下载模板由 Excel 保存。Prompt 内容原样保存，不裁剪或替换换行。CSV 错误行号为物理起始行，因此前面有多行 Prompt 时不等于方案序号。XLSX 使用 `submissions` 表或第一张表，不执行公式；公式单元格会被拒绝，防止导入时产生不可复现的数据。每次最多 100 份，文件最大 8MB。

API Key 与环境变量二选一。真实 API 需公网 HTTPS 443/8443，复用原 SSRF 校验。只做 DNS / 地址校验，不进行收费 HTTP 模型测试。使用环境变量时填的是主办方服务进程的环境变量名；缺失环境变量会在创建批次预览时阻止整批创建。Mock 配置的 URL、API Key 和环境变量均留空。

同一 `team_id + submission_version` 完全重复会跳过，不创建重复模型或 Prompt；内容不同须用新版本号，禁止覆盖历史。一个队伍多个方案版本均保留。同一 `team_id` 使用一致队伍名。版本冲突或事务失败会整体回滚。

上传原始文件不落盘。预览仅返回安全字段，规范化配置在临时预览表中加密存储，最多一小时可确认；确认后清除暂存密文，只保留无密钥的确认结果供幂等重试。重新预览会清理过期暂存密文。API Key 另按现有机制加密保存。预览、错误响应、报告和排行榜不会回显 Key，模板没有真实密钥。

模板下载：

- `/api/submissions/template?format=xlsx`
- `/api/submissions/template?format=csv`
- 追加 `&mock=true` 下载 5 支 Mock 队伍样本。样本同样经过真实 CSV/XLSX 解析、预览、确认流程。

## 正式比赛 03 批量测评与监控

1. 选择方案，支持筛选、全选筛选结果和取消；同一批次每队只能选一个版本。
2. 填写批次名称，统一选择推理策略、每题次数及提前结束规则。**批量测试开关默认开启**；预算与超时读取主办方设置。
3. 点击“预览计划与请求上限”，确认队伍数、每队题数、总 QA、请求上限、模式、截图与题库完整性和费用说明。
4. 点击“保存冻结批次”，只创建草稿和各队独立 `run_id`，**不会发起模型请求**。
5. 在批次列表单独点击“启动批次”。正式比赛须在确认窗口核对冻结批次名称、队伍数、每队题数、最大模型 API 请求数、推理模式及实际 API 费用提醒，主动确认后才启动。启动后所有队伍自动排队，无需逐个点击。

开关开启为 **批量测试｜非正式成绩**，请求 `official=false`。可选择一队或多队、维度、题数或题目 ID，也可使用 Mock；四维准确率、调用记录、分析及导出仍可查看，成绩不会进入正式榜。

开关关闭为 **正式比赛｜全量 1,279 道 QA**，请求 `official=true, dimension=null, limit=null, question_ids=[]`。界面自动选择全部四维，清空并禁用局部筛选；后端预览、创建和单任务准入同样拒绝任何正式筛选，即使显式指定全部题目或题数为 1279 也会拒绝。正式批次必须使用真实模型、完整四维题库及每题对应的真实截图，Mock 或缺图会在预览阶段被阻止。

切换开关只改变测试/正式属性，不改变三种推理策略。切换或修改配置后旧预览立即清除，保存按钮禁用；旧预览的延迟响应不会恢复保存权限，必须重新预览。切换本身不会创建或启动任务。批次列表、监控及分析页显示同一模式名称。

Single-pass 固定一次且次数为只读；Self-refine / Majority-vote 可选 1～主办方上限。Self-refine 次数包含首轮作答，Review 后续调用也占预算。其他模式不允许启用提前结束。官方最大次数与超时无需修改源码即可配置。

创建时冻结模型、凭据、三段 Prompt、原题、GT、截图哈希、预算、超时、权重、范围和规则。某一队模型错误仍照常记录并计错，不阻止后续队伍。创建和启动均幂等；重复点击启动不会重复排队。未完成状态不会被当成最终成绩。

界面每 3 秒刷新整批队伍状态、完成 QA、请求次数、耗时和错误数。支持停止整批或通过逐队“停止该队”安全停止。当前请求完成/超时后不再发起下一次；队列中尚未执行的停止任务不会发送请求。

## 正式比赛 04 竞赛分析与导出

选择一个批次、队伍筛选、Top 5 / Top 10 / 全部。四类图表全部来自实际运行结果：

- 横向综合得分条形图，0～100 分。
- 四维准确率分组条形图，0～100%，缺失维度不伪造数据。
- 四维能力雷达图，显示当前图表范围排名前两队，可通过队伍筛选指定一队或两队。
- 推理效率散点图：横轴平均单题推理秒数，纵轴综合得分；点大小为平均每题请求数。缺失耗时不当成零，Mock 耗时只作联调观察。

排名按 35/35/15/15 直接复用原评分器。每批仅使用 `batch_entries` 当前绑定的一队一份成绩，不从历史选择最高分。未完整完成、存在主办方基础设施故障、正式但不满足准入条件的运行列为排除项。Mock、真实模型局部测试、正式成绩分组，数据/截图 cohort、模式、实际预算、提前结束设置不同也分别排名。历史排行榜同样新增批次与执行条件分组。

主办方故障重跑沿用原接口，在保留旧记录且标记 `superseded` 的同时，把该批次该队的有效绑定移动到新 `run_id`，不重复占位。某队中断后没有完成重跑时不会进入最终排名。

### 综合 HTML 报告

在分析页选择公开版或管理员统计详细版，再点击“导出综合 HTML 报告”。单个 HTML 内嵌样式与四种 SVG 图表，断网可直接打开或打印，不加载外部脚本、字体或 CDN。

包含整批统计、筛选范围、分组排行榜、四维对比、雷达、效率分析、排除项和评分口径。图表使用当前队伍筛选与 Top N，表格保留所选范围全部可排名队伍；雷达仅显示图表范围前两队。顶部指标明确标记为整批统计，防止与筛选图表混淆。

公开版和管理员版均不包含 API Key、凭据环境变量引用、Prompt 正文、GT、参考推理或模型逐题输出。管理员统计详细版额外提供安全的 run_id、提交/Prompt 版本、错误次数和 Token Usage 追溯表。原 V1.1 单次任务导出保持兼容。

### 图表导出

每张图都有 SVG 和 PNG 导出。SVG 为后端从相同分析数据生成的矢量图；PNG 在浏览器本地用 Canvas 对同一张 SVG 转换，不发送数据到第三方服务，默认双倍像素。下载结果会保留类型、模式、组、单位和具体数值。离线综合 HTML 已内嵌 SVG；PNG 下载按钮在管理界面使用。

排行榜同时支持 CSV/XLSX，完整安全分析数据支持 JSON。所有导出复用相同批次、队伍筛选和 Top N。CSV 准确率列为 0～1，HTML/图表按百分比显示；综合分始终为 0～100。CSV 对公式前缀加单引号，XLSX 字符串以纯文本写入。

## 增量数据表

| 表 | 用途 |
|---|---|
| `teams` | 稳定队伍编号与名称 |
| `submissions` | 队伍方案版本、模型/Prompt 绑定、凭据不可逆校验摘要 |
| `import_previews` | 加密临时导入预览与安全幂等确认结果 |
| `evaluation_batches` | 幂等创建标识、批次名称、主办方请求与预览快照、启停标记 |
| `batch_entries` | 每队方案与当前有效 run 的绑定 |

原 `runs`、`results`、`calls` 继续保存执行快照、结果与逐次调用，未重写推理引擎。

## 新 API

```text
GET  /api/submissions/template?format=xlsx|csv&mock=true|false
POST /api/submissions/batch/preview        multipart file
POST /api/submissions/batch/import         {"preview_id":"…"}
GET  /api/submissions

POST /api/evaluation-batches/preview
POST /api/evaluation-batches
GET  /api/evaluation-batches
GET  /api/evaluation-batches/{id}
GET  /api/evaluation-batches/{id}/progress
POST /api/evaluation-batches/{id}/start
POST /api/evaluation-batches/{id}/stop
GET  /api/evaluation-batches/{id}/leaderboard
GET  /api/evaluation-batches/{id}/analytics
GET  /api/evaluation-batches/{id}/charts/{ranking|dimensions|radar|efficiency}.svg
GET  /api/evaluation-batches/{id}/export?format=html|json|csv|xlsx&audience=public|admin
```

创建/预览请求使用相同字段：`request_key`（至少 8 字符的幂等键）、`name`、`submission_ids`、`mode`、`calls`，可选 `early_stop`、`official`、`dimension`、`limit`、`question_ids`。相同幂等键对应不同请求会拒绝，不静默复用。

启动正式批次须向 `/api/evaluation-batches/{id}/start` 提交 `{"confirm_official":true}`；缺少确认或值为 false 会拒绝启动。测试批次仍兼容无请求体的启动方式。

分析与导出允许重复 `team_id` 参数筛选队伍，以及 `top=5|10|0`（0 表示全部）；SVG 还需 `group` 为分析 API 返回的组 ID。所有源数据均来自已有 SQLite，不调用参赛模型。
